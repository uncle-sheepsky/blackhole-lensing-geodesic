# blackhole-lensing-geodesic

**슈바르츠실트 블랙홀을 코드로 그리는 최소 렌더러.** 각도·줌·노출을 바꿔도 **같은 블랙홀**이
유지됩니다 — 같은 값을 넣으면 언제나 같은 그림이 나오기 때문입니다.

라이선스 **CC0 1.0**. 마음대로 쓰고 고치세요.

```bash
# 1) 그냥 열기 — 서버도 설치도 필요 없습니다
src/blackhole.html          # 슬라이더로 incl / az / zoom / expo / fov / t

# 2) 물리가 맞는지 코드가 검사합니다
node src/verify.mjs

# 3) 정지 프레임 굽기 (playwright 필요)
npm i playwright && npx playwright install chromium
node src/still.mjs                    # incl 76 / 32 / 88 → out/
node src/still.mjs --incl=20,45,70 --check
```

## 이 저장소의 범위 — **블랙홀 재현까지**입니다

| 들어 있는 것 | 없는 것 |
|---|---|
| 렌징 셰이더 · CPU 측지선 적분기 · 뷰어 · 물리 검사 · **프롬프트** | 영상 편집 자산(컴포지션·자막·나레이션·음악·폰트·컷 표) |

영상은 이 렌더러를 **소재로** 만들었지만, 이 저장소는 **영상 재현 패키지가 아닙니다.**
「영상을 그대로 다시 굽는 코드」를 기대하고 오셨다면 여기엔 없습니다 — 여기 있는 것은
**블랙홀을 그리는 부분**과, 그걸 AI에게 시킬 때 쓴 **프롬프트**([`PROMPTS.md`](PROMPTS.md))뿐입니다.

## 무엇을 계산하나

- **광자 측지선을 카메라에서 거꾸로 적분**합니다(backward ray tracing). 픽셀마다 광선 하나.
  `acc = -1.5 · h² · pos / r⁵` (h = |pos × vel| = 보존되는 각운동량) 를 **320스텝** 적분합니다.
- 광선이 **적도면(y=0)을 지날 때마다** 강착원반 방출을 누적합니다 — 한 광선이 여러 번 만나므로
  블랙홀 **뒤쪽** 원반이 위아래로 감겨 보입니다(2차상).
- 밝기 = 상대론 **도플러 빔잉** `dopp³` × 중력 감쇠 `√(1−Rs/r)`.
  ⚠**색을 바꾸는 것은 도플러뿐**입니다. 중력항은 밝기만 깎습니다.
- 상수: `RS = 1.0` · `DISK_IN = 2.4` · `DISK_OUT = 10.0` · `STEPS = 320` · `DT = 0.14`.
  셰이더(GLSL)와 CPU 판본(JS)이 **같은 상수를 한 곳에서** 받아 씁니다.

## 코드가 스스로 검사합니다 (`verify.mjs`)

| # | 검사 | 판정 |
|---|---|---|
| 1 | 결정론 — 같은 입력이면 측지선이 **비트까지 동일** | 같은 값 → 같은 그림 |
| 2 | 약장 편향각 → **4M/b** (2차항 `15πM²/4b²` 까지 대조) | b≥60 에서 1차항 오차 ≤3% |
| 3 | 임계 임팩트 파라미터 → **3√3·M = 2.598 Rs** | 오차 ≤1% |
| 4 | 그 반경 **안쪽은 포획 · 바깥은 탈출** | 화면 좌표 ↔ 임팩트 파라미터 매핑 |
| 5 | 적도면 **2회 통과** 광선이 실재 | 아래 초승달 = 뒤쪽 원반 |
| 6 | 도플러 빔잉 — 같은 반경에서 좌우 밝기 차 | 자른 자리 탓이 아니다 |

## 결정론에 대해 — 실 GPU 는 픽셀이 갈립니다

같은 프레임을 순서만 바꿔 두 번 그리면 **RTX 3060 / ANGLE D3D11 에서 최대 Δ8/255** 가
수백 픽셀에 흩어져 나왔습니다. 그래서 `still.mjs` 는 기본을 **SwiftShader(소프트웨어 래스터)** 로
둡니다. 빠르게 보기만 할 거면 `DET_SW=0` 를 주세요.

`?preview` 같은 것도, 애니메이션 루프도 없습니다 — 슬라이더를 움직일 때만 그립니다.
`rAF` · `Date.now` · `Math.random` 을 쓰지 않는 것이 결정론의 전부입니다.
